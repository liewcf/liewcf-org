# Static Astro Migration Handoff

Date: 2026-07-26
Status: Release-ready repository; production deployment not performed

## Implemented site

`liewcf.org` is generated by Astro in static output mode. It publishes:

- the profile homepage;
- a factual About page;
- a four-Project catalog and four repository-slug detail pages;
- an empty-launch Updates index and RSS feed;
- a branded noindex 404 page;
- a generated sitemap and Markdown profile; and
- the established crawler, security, well-known, Agent Skill, WebMCP, favicon, image, font, and texture resources.

Projects and Updates use typed local Markdown collections with production draft exclusion. Every Update has a non-empty body and belongs to exactly one existing Project. There are no published Updates at handoff.

## Architecture boundary

- Astro is a build and preview tool only.
- Output mode is static, with no adapter or SSR.
- Browser behavior is vanilla JavaScript.
- Styling is plain CSS.
- Contact remains outbound `mailto:` only.
- There is no database, runtime API, Cloudflare Pages Function, runtime environment variable, Tailwind stack, or client-side UI framework.
- The Markdown content model remains compatible with a future Decap CMS phase, but this release has no `/admin/`, Decap bundle, authentication configuration, backend configuration, or secret.

## Commands

```sh
npm install
npm run dev
npm run check
```

`npm run check` is the single release gate. It runs Astro diagnostics, valid and invalid Update fixture builds, a clean production build, and the Playwright production-output contract suite.

## Cloudflare Pages contract

- Build command: `npm run build`
- Output directory: `dist`
- Runtime environment variables: none

Generated `dist/_redirects` must contain only:

```text
/.well-known/api-catalog /.well-known/api-catalog.json 200
/contact/ / 301
```

About, Projects, Updates, and Project detail pages are live static output and must not be redirected. Blog routes intentionally have no redirect and receive the branded real 404 response.

Generated `dist/_headers` must preserve:

- HSTS;
- the existing CSP and `frame-ancestors 'none'`;
- `X-Frame-Options: DENY`;
- `X-Content-Type-Options: nosniff`;
- the referrer and permissions policies;
- discovery Link headers; and
- content-type overrides for API catalog, security contact, `llms.txt`, generated Markdown, RSS, and Agent Skill resources.

Do not weaken these protections to accommodate Astro output or browser scripts.

## Release gate evidence

Before integration, run `npm run check` from this repository and record the exact Playwright count in project memory. Representative desktop and mobile browser checks must include the homepage, About, Project catalog, every Project detail, Updates index, branded 404, keyboard skip-link behavior, visible focus, reduced motion, and horizontal-overflow checks.
